# 豆阵后端与兑换交付设计

## 目标

为原创拼豆图纸提供真实账户、一次性兑换码、已购图纸和分区进度服务。支付仍由外部虚拟商品渠道处理，本站不收集支付信息。

## 首版架构

保留公开展示页，功能版以一个 Node 服务运行：网页、API 和 SQLite 数据库位于同一服务。数据库挂载到持久化目录，避免重新部署后丢失账户、兑换码和进度。

服务边界：

- 前台：图纸库、注册/登录、兑换、我的图纸、制作台。
- 后台：图纸发布、兑换码批量生成、未使用码作废、兑换状态查询。
- 外部渠道：收款、退款与发送兑换码；本站只验证兑换码并授予图纸。

## 最小客户信息

| 字段 | 用途 | 不收集的替代信息 |
|---|---|---|
| 邮箱 | 登录账号、找回与必要服务通知 | 姓名、手机号、地址 |
| 密码哈希 | 校验登录 | 明文密码 |
| 图纸权益与进度 | 提供已购图纸和跨设备进度 | 支付账户、银行卡信息 |

用户可在账户内申请注销。注销时删除邮箱和密码哈希；兑换审计只保留匿名用户标识与兑换时间，避免被注销账户的兑换码再次使用。

## 数据模型

### users

- `id`：随机 UUID。
- `email`：小写标准化后唯一。
- `password_hash`：bcrypt 哈希。
- `role`：`member` 或 `admin`。
- `created_at`、`last_login_at`。

### patterns 与 pattern_sections

`patterns` 保存发布版本的作品规格：标题、版权声明、产品线、品牌色卡版本、成品尺寸、总板数、总颗数、总颜色数与封面。

`pattern_sections` 保存每个分区：分区编号、网格尺寸、每格品牌色号、该分区色号统计、制作说明。发布后图纸版本不可覆盖；改色发布新版本，已购用户继续读取原版本。

### redemption_batches 与 redemption_codes

`redemption_batches` 记录一次导出给外部发码渠道的图纸、数量、创建时间与管理员。

`redemption_codes` 保存：

- 图纸版本 ID 与批次 ID。
- `code_hash`：兑换码标准化后的 SHA-256 哈希，唯一。
- `status`：`active`、`redeemed`、`revoked`。
- `redeemed_by`、`redeemed_at`、`revoked_at`。
- 可选 `external_order_ref`，只保存外部订单引用号，不保存支付信息。

明文兑换码仅在后台生成时返回一次，之后不可查询。

### entitlements、section_progress 与 admin_audit_logs

- `entitlements`：用户拥有的图纸版本与授予时间。
- `section_progress`：`user_id + pattern_id + section_id`，记录完成状态与更新时间。
- `admin_audit_logs`：图纸发布、码批次生成、作废和人工补发，不记录密码或明文兑换码。

## 关键流程

### 兑换

1. 用户登录并提交兑换码。
2. 服务端规范化兑换码、哈希并查询有效状态。
3. 使用单个数据库事务同时完成：标记码已兑换、写入权益、写入审计记录。
4. 返回图纸制作台地址。
5. 已兑换、已作废、无效的兑换码都不授予权益；接口返回统一错误文案，不暴露码存在与否的细节。

### 制作台

1. 用户请求图纸时，服务端先验证 `entitlements`。
2. 返回当前图纸版本、色卡、全图统计和有权访问的分区。
3. 分区进度写入 `section_progress`，只允许该图纸的权益用户更新。

### 外部发码

第一阶段手工导出某一批兑换码到外部虚拟商品自动发货渠道。后续如渠道提供签名回调，再由回调接口验证签名并写入 `external_order_ref`；支付数据仍留在外部渠道。

## 安全与合规

- 密码使用 bcrypt；会话用 HttpOnly、Secure、SameSite=Lax Cookie。
- 兑换码使用至少 128 位随机熵；只保存哈希。
- 登录与兑换接口按 IP 和账户限流；连续失败后短时冻结。
- 所有图纸、进度和后台接口均在服务端校验角色与图纸权益。
- 每日备份 SQLite 文件到独立受限位置；恢复演练后再宣称可恢复。
- 上线时提供隐私政策、账户注销入口和联系渠道。客户资料仅用于账户与已购图纸服务，不作广告画像或向外部出售。

## 部署

首版选择带持久化卷的 Node 托管服务：

- `DATABASE_PATH=/data/pixel-mural.sqlite`
- `SESSION_SECRET` 为生产随机密钥。
- 数据卷挂载 `/data`。
- 部署前不包含 `.env.local`、数据库文件、日志和明文兑换码。

GitHub Pages 保留为公开展示站。功能版上线后，展示站的“兑换”与“我的图纸”入口改为跳转功能站。

## 验收

1. 用户注册、登录、注销可用，密码从不以明文保存或返回。
2. 有效码只能兑换一次；同一数据库事务生成图纸权益。
3. 用户只能查看和更新自己的图纸及进度。
4. 后台生成明文码一次后，只能看到状态，不能再次读取明文。
5. 每张正式图纸显示固定品牌、色号、全图总数、分区总数、全图与分区颜色清单。
6. 重新部署后，测试账户、兑换记录和进度仍存在。
